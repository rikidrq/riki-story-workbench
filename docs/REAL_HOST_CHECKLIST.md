# 真实酒馆验收清单

本清单需要用户在实际 SillyTavern/Tavern Helper 中执行。自动化不能代替这些结果。

## 1. 导入与版本加载

- [ ] 运行 `npm run preview`，保持本地服务器开启。
- [ ] 导入 `dist/酒馆助手脚本-Riki剧情工作台-本地开发加载器.json`。
- [ ] 脚本按钮显示「打开 Riki 剧情工作台」。
- [ ] 点击按钮和右下角 R 都只能打开一个工作台实例。
- [ ] 诊断页显示实际 ST/TH 版本和必要能力。
- [ ] 把加载器版本改成不存在的版本，能看到明确失败提示，不继续伪装成功。
- [ ] 改回 `1.2.0` 后刷新，能重新加载。

## 2. 模型连接与设备配置

- [ ] 酒馆当前连接可讨论和生成正式成果，主聊天不新增楼层。
- [ ] Connection Manager profile 列表与酒馆一致，流式显示、停止和错误均正常。
- [ ] 独立 OpenAI-compatible 在允许跨域的 HTTPS 网关上可流式显示；错误网关显示 CORS/HTTPS/不可达诊断。
- [ ] 新建、切换、保存、删除 API 配置；刷新和重新导入脚本后仍保留。
- [ ] 新建、复制酒馆 System、切换与删除自定义 System 预设。
- [ ] 主控、次 Agent 默认、模块覆盖和格式编译继承与界面解析摘要一致。
- [ ] 项目 metadata、项目导出、请求日志和世界书中搜索不到测试 API Key。

## 3. 世界书只读

- [ ] 使用一个可丢弃聊天和测试世界书。
- [ ] 世界书列表、角色绑定、聊天绑定、全局标签与酒馆实际一致。
- [ ] 条目标题、UID、策略、关键词、位置、正文读取正确。
- [ ] 切换聊天后旧工作台关闭；重新打开读取新聊天状态。

## 4. 写入、冲突与撤销

- [ ] 修改一条测试条目，Diff 前世界书没有变化。
- [ ] 确认写入后，酒馆世界书编辑器显示新值；刷新页面后仍存在。
- [ ] 在 Diff 打开后，从酒馆编辑器修改同一条目，再点确认；工作台必须拒绝覆盖。
- [ ] 同时从两个 Riki 页面修改同一本世界书；预期 Riki 自身写入串行化，后发的陈旧 Patch 被拒绝。
- [ ] Riki 与酒馆原生编辑器在同一瞬间写入；记录宿主无原子 CAS 时的实际行为，不把 updater hash 检查误写成绝对并发保证。
- [ ] 点击撤销后恢复上一版本；刷新页面后仍存在。
- [ ] 工作台写入不改变同书其他条目和未知字段。

## 5. Agent、消息与正式成果

- [ ] 新建、复制偏好、重命名、切换和删除 Agent 分支；最后一个分支不会被删空。
- [ ] 用户消息编辑/删除、助手重 Roll/复制/删除均可用；生成中点击重 Roll 不会丢回复。
- [ ] 流式文本逐步出现；停止保留已收到内容；关闭工作台后后台完成，重开可见。
- [ ] 总纲、大章、小章、人物分别能形成正式候选；推进预设没有 Agent、成果或配置入口。
- [ ] 大章/小章/人物子项能确认、打回并只重做被打回项。
- [ ] 两个分支基于同一版本生成候选；先确认一条后，另一条必须因 stale 拒绝覆盖。
- [ ] 成果版本、Diff、基于当前版本修改、级联删除、整批恢复和永久清空都可操作。
- [ ] 详细版、粗略人物确认→精细人设、懒人版五步→统一确认/整批回滚完整走一轮。

## 6. 独立剧情讨论

- [ ] 选择 1–3 个条目作为上下文。
- [ ] 发送一次剧情讨论，模型返回正常。
- [ ] 主聊天没有新增楼层。
- [ ] 切换到不同聊天后讨论记录隔离。
- [ ] 模型修改提案只能载入编辑器，不能自动写世界书。
- [ ] 无 `generateRaw` 或请求失败时显示错误，不自动切换其他连接。

## 7. 项目、日志与 Command Core

- [ ] 项目导出保留全部成果版本链和分支偏好，不含 API 配置/Key/日志/消息。
- [ ] 新聊天导入项目；已有成果时明确替换并可从回收站恢复旧成果。
- [ ] 诊断页可切摘要/完整输入/完整输出并导出，所有密钥仍脱敏。
- [ ] `status`、分支、成果、模型解析、世界书两阶段写和策划发送 Command Core 返回正确。

## 8. 手机与生命周期

- [ ] 320、375、430px 宽度分别打开。
- [ ] 底部三段导航可用，输入框不会被软键盘永久遮挡。
- [ ] 长世界书名、长条目名和长正文可滚动，不横向溢出。
- [ ] 横竖屏切换后仍可编辑和关闭。
- [ ] 320px 点击右上 × 后遮罩完全消失，右下 R 可重新打开。
- [ ] 脚本热重载、禁用或切聊天后没有重复 R 按钮、重复监听或多个工作台。

## 9. 驾驶员验收

- [ ] 用户确认 1.2 的原版同构 UI、四成果工作流、手机/电脑操作和版本更新方式符合预期。
- [ ] 确认 GitHub/jsDelivr 正式地址能按 `RIKI_VERSION` 加载对应 `v<version>` 标签和版本目录。
