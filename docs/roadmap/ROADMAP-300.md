# Riki 后续版本走向 · 300 字摘要

以下是面向快速决策的摘要；详细设计仍保留在同目录的四份长文中。它们都是路线设计，不代表相应功能已经实现。

## 2.0 · 轻量公共剧情记忆

2.0 在 1.1 的策划成果与分支会话之上增加一层轻量记忆，不复制当前庞大记忆插件。它只保存已确认事件、人物关系变化、未回收伏笔、用户偏好和必要摘要，并给每条记录稳定 ID、来源楼层、置信度、可见范围与失效条件。生成前按当前任务检索少量相关记忆，生成后先形成候选，由用户确认、合并或拒绝；不让模型直接改历史。电脑端提供时间线、检索和冲突对照，手机端提供抽屉式记忆卡片与快速确认。默认本地、可导出、可清空，设严格字符与条数预算；无记忆引擎时 1.1 全功能仍可独立运行。验收重点是长聊天恢复速度、错误摘要撤销、分支隔离和同一事实多来源合并；任何召回失败都只降低为无记忆策划，不能阻塞对话、成果或世界书工作流。

## 2.5 · 角色卡模板迁移

2.5 把不同角色卡中的 MVU、SP 数据库或自定义 JSON 模板转换到 Riki 的统一中间模型，但不要求原卡永久依赖某一种数据库。流程是只读扫描角色卡、世界书、脚本、正则和变量声明，识别字段绑定与运行依赖，生成迁移报告和可回滚预览，再由用户选择目标适配器。迁移器使用稳定字段 ID、版本化 schema、确定性 migration 和兼容性矩阵；不理解的字段保留在隔离区，绝不静默丢弃。电脑端适合字段映射与 Diff，手机端只做审阅和确认。最终可输出新组件或迁移包，但不会自动覆盖原卡，真实酒馆导入仍是单独验收门。每次迁移还要生成字段去向、行为差异、丢失风险和回退文件清单，并用固定夹具复测初始化、更新、显示与导出，避免“JSON 能导入”却在运行中悄悄失效。

## 3.0 · 多二创 Provider 平台

3.0 把灵感二创、生图、素材库、剧情大纲衍生和未来其他创作服务做成可插拔 Provider，而不是重新把它们焊死进剧情助手。每个 Provider 声明输入类型、输出资产、模型与费用、权限、敏感数据范围、进度事件、取消能力和失败回退。1.1 的正式成果与 2.0 的已确认记忆只能作为用户明确选择的只读素材；二创结果先进入独立素材草稿箱，不反向修改世界书或剧情事实。电脑端提供多任务队列、版本对比和素材管理，手机端提供任务状态、预览、取消与收藏。某个 Provider 缺失或失效时，剧情策划主链仍完整可用。平台会对付费调用、外部上传、成人内容、版权来源和资产删除分别确认，并保存来源、参数与版本收据；批量任务可暂停、续跑和逐项失败，不因一个供应商异常丢掉整批素材。

## 4.0 · 每角色独立记忆生态

4.0 在公共事件账本之上，为每个由用户或 AI 扮演的角色建立独立认知记忆。角色只能记住其亲历、被告知或合理推断的内容，并区分事实、传闻、误解、情绪印象、关系判断与秘密；同一事件可在不同角色中形成互相矛盾的记忆。记忆更新先经过事件分发、知识边界检查与候选确认，禁止全知信息泄漏。界面提供角色视角切换、记忆来源、矛盾图和“为什么他知道”追踪，手机端以角色抽屉快速查看。系统支持遗忘、纠错、合并、备份和按角色导出，并设置每角色容量、检索延迟与生成预算，避免人物越多性能越差。群聊、换角色扮演、分支回溯和谎言揭穿是重点验收场景；系统必须能说明某条认知从哪次观察或转述而来，也能在来源撤销后确定性地重算受影响的角色记忆。
