# Riki 剧情工作台 V3.0 路线说明：多灵感二创与 Creative Provider 平台

> 文档状态：方向设计稿，不代表任何二创、生图、素材库或第三方服务已经接入。V3.0 只有在 V1.1 主工作台、V2.0 公共记忆和 V2.5 统一角色项目标准分别通过自己的发布门后才能实施。本文描述 Provider 架构与产品边界，不构成对外部服务可用性、价格、许可证或内容政策的承诺。

## 一、版本定位

V3.0 要解决的不是“在 Riki 里再放一个生图按钮”，而是把灵感二创从主工作台的硬编码功能拆成多个可插拔、可审计、可替换的 Creative Provider。一个 Provider 可以负责文字灵感、场景变体、人物服装、图片、封面、分镜、素材检索或其他创意输出；不同 Provider 可能使用酒馆当前模型、独立 OpenAI-compatible API、本地服务、浏览器内算法或外部应用。Riki 负责统一输入、任务、权限、状态、结果、来源、成本和失败回退，不把某一家服务写死成产品本身。

用户最初设想“有可能有多个二创，比如生图什么的”，关键价值就在“多个”。同一个剧情节点可以先让文本灵感 Provider 给出三个方向，再把被选方向交给视觉提示词 Provider，最后交给一个或多个生图 Provider。用户也可以完全不生图，只使用大纲变体；或者关闭云端，只用本地模板与素材。Provider 之间通过稳定的 Creative Job 与 Artifact 契约协作，而不是彼此调用私有全局函数。

这一版要保留 Riki 的严谨边界：创意结果默认只是候选素材，不是世界事实，不会自动写世界书、记忆、角色卡或主聊天；用户明确“采用”后，才进入对应的 V1.1 成果提案、V2.0 记忆候选、V2.5 资源组件或聊天发送流程。二创可以大胆，落地必须受控。

## 二、目标与成功标准

第一目标是统一不同创意能力的使用体验。用户不必记每个服务的专有页面和参数：在当前剧情、成果或角色上选择“创作”，挑任务类型、输入范围与 Provider，看到费用/隐私提示，启动后统一查看进度、取消、重试、比较和采用结果。

第二目标是让 Provider 真正可替换。Riki 核心只依赖能力声明和输入输出 schema。某个图片服务下线、跨域失败或不适合手机时，用户可以换另一个 Provider；文本灵感可以走 V1.1 当前连接，也可以走独立预设；本地确定性 Provider 在断网时仍能工作。更换不应破坏项目数据或历史成果。

第三目标是安全与可追溯。每个任务记录使用了哪些用户资料、哪个 Provider、哪个配置引用、什么模型描述、参数、时间、成本估算和输出哈希。密钥不进入任务历史或项目导出。远程输出在被采用前视为不可信数据，图片和富文本需经过类型、大小和活动内容检查。

第四目标是完整的手机与电脑体验。电脑端适合多结果对比、分镜和素材管理；手机端必须能从当前剧情发起、查看进度、取消、预览、选择、下载或采用，不允许出现按钮藏在 hover、弹窗关不掉、软键盘挡参数等老问题。

成功标准包括：至少三种不同类型 Provider 的端到端纵切；至少两个同类 Provider 可互换；任务取消和失败不会污染成果；输出采用走正确的受控通道；隐私与密钥扫描通过；桌面和 320/375/430px 自动化逐按钮验证；真实宿主验证生成、后台恢复、切聊天和资源落地。外部服务的模拟测试不能替代至少一条获得授权的真实服务验证。

## 三、明确非目标

V3.0 不把旧“灵感二创”整包应用壳、游戏化能量、卡池、商店、成就、衣柜、邂逅和数据库运行期原样塞回核心。那些产品能力可以被重新评估为独立 Provider 或上层玩法包，但必须逐一通过需求、权限和数据契约，不因旧项目存在就默认迁入。

V3.0 不运营开放式插件商店，不允许从任意 URL 动态执行 Provider 代码，不自动安装第三方依赖。首发 Provider 应内置、随版本固定，或由用户明确本地安装并经过 manifest/权限检查。远程服务端是数据处理端，不是向浏览器注入代码的渠道。

V3.0 不承诺无限模态。首发可聚焦文字灵感、视觉提示词和静态图片；音频、视频、Live2D、3D 或复杂编辑器只有在真实需求、性能和宿主能力明确后再扩。文档可以预留媒体类型，但 UI 不用未实现按钮占位冒充功能。

V3.0 不自动把创意输出变成剧情真相，不自动写世界书、不自动确认 V2.0 记忆、不自动覆盖角色立绘、不自动发送主聊天。也不负责 V4.0 每角色独立记忆。Provider 可以读取用户授权的角色视角资料，但不能维护角色心智状态。

V3.0 不替用户承担外部服务费用、版权和内容合规判断。产品负责清晰展示数据去向、配置来源、估算与保存信息，用户负责选择有权使用的模型、素材和发布范围。

## 四、核心概念

`CreativeProvider` 是能力实现者；`CreativeCapability` 是它声明能完成的任务，如 `idea.branch`、`text.rewrite`、`image.prompt`、`image.generate`、`image.variation`、`asset.search-local`；`CreativeJob` 是一次可取消、有状态的执行；`CreativeArtifact` 是输出；`CreativeRecipe` 是一条可重放的多步骤流程；`CreativeWorkspace` 是用户比较、选择和采用结果的界面。

Provider 与模型预设不是同一概念。一个 Provider 可以内部使用 V1.1 的模型配置，也可以使用自己的设备级连接；Provider manifest 必须声明配置 schema 和敏感字段，Riki 只保存非敏感引用。模型名称、采样参数和尺寸是任务参数，API Key 仍留在设备级 Secret Store 或宿主 Connection Manager。

Artifact 分为文本、结构化数据、图片、音频、视频、外部资源引用和组合包。每个 Artifact 有稳定 ID、任务 ID、媒体类型、内容哈希、尺寸、预览、来源、许可证/用户声明、风险扫描、采用状态和生命周期。临时输出与已采用资产分开保存，用户清理缓存不会误删已进入项目的资源。

Recipe 不是任意代码，而是声明式有向步骤：输入选择、Provider 能力、参数映射、人工确认门和输出去向。首发禁止无限循环和动态脚本。每步失败有停止、跳过、换 Provider 或使用上一步结果的回退策略。

## 五、典型用户流程

### 5.1 从剧情节点找灵感

用户在对话、总纲、大章或小章成果上点击“创作”。弹出的作用域面板明确列出将发送给 Provider 的内容：当前选段、角色摘要、可选世界书条目、可选 V2.0 记忆胶囊。默认采用最小输入，用户主动勾选才增加资料。随后选择“分支灵感”“冲突升级”“伏笔回收”“氛围变体”等任务和 Provider。

任务开始后显示排队、运行、流式、等待用户、完成、失败或取消状态。文本结果以可比较卡片展示，包含 Provider、参数、输入摘要和风险提示。用户可以收藏、局部编辑、让同一或另一 Provider 继续扩写。只有点击“转为成果候选”“填入输入框”或“保存到素材”后，结果才离开临时区。

### 5.2 从人物生成视觉方案

用户在人物成果或 V2.5 统一角色组件上选择“视觉方案”。第一步由视觉提示词 Provider 把已授权的人物描述转成结构化设计：外观固定项、服装、姿态、场景、镜头、风格、负面限制。用户逐项确认后再选择生图 Provider、尺寸、数量和内容等级。

生成过程显示费用或配额估算、是否上传参考图、预计保存位置。多个 Provider 的输出可以并排比较，不用强制统一参数。用户采用某张图时选择用途：项目临时素材、人物立绘候选、封面、场景图或下载。写入 V2.5 资产清单前显示文件名、哈希、来源、许可证说明和替换 Diff。

### 5.3 多步 Recipe

用户选择“章节灵感到场景图” Recipe：文本 Provider 给出三条场景方向 → 用户选择一条 → 提示词 Provider 形成结构化提示词 → 生图 Provider 生成四张图 → 用户挑选一张保存。每个人工门都可退出并保存中间结果；重新打开从检查点继续。任何步骤换 Provider 都保留旧结果，便于比较。

### 5.4 失败与换路

若首选 Provider 因 CORS、配额、内容政策或服务不可达失败，任务卡显示明确分类、已发送与未发送状态、是否可能扣费、可安全重试与否。用户可选择重试、换同能力 Provider、仅保存输入或回到上一步，系统不静默改走其他代理或降低内容限制。

## 六、Provider Manifest

每个 Provider 必须有静态 manifest：稳定 ID、版本、显示名、作者、许可证、实现类型、支持能力、输入/输出媒体、配置 schema、敏感字段、权限、网络域名、并发限制、超时、取消支持、费用描述、内容限制、数据保留说明、宿主要求和回退建议。

实现类型至少区分 `local-deterministic`、`tavern-model`、`openai-compatible`、`local-service` 和 `external-service`。这个分类影响配置和隐私提示，但不代替实际权限。即使是“本地服务”，也要声明 URL、是否离开浏览器、是否保存数据。

能力声明要细化输入与输出。例如图片 Provider 是否支持文生图、图生图、蒙版、参考图、透明背景、种子、尺寸和批量；文本 Provider 是否支持流式、结构化 schema、长上下文和中文。UI 只展示 manifest 声明且已通过能力探测的选项，不能让用户填了参数才发现不支持。

manifest 版本与实现版本固定绑定。更新 Provider 时显示能力、权限、域名和默认值 Diff。新增网络域名或数据类型视为权限升级，需用户重新确认。Provider 不得在运行时从远端修改自己的 manifest。

## 七、统一任务与状态机

`CreativeJob` 包含 jobId、projectId、chatKey、capability、providerRef、configRef、inputRefs、redactedInputSnapshot、parameters、state、progress、attempts、artifacts、cost、timestamps、errors 和 audit。输入优先保存引用与哈希；若为恢复任务必须保存快照，则按隐私策略加密或明确标记本地敏感数据。

状态机为 draft → awaiting-consent → queued → running → streaming/processing → completed/failed/cancelled；多步任务可进入 awaiting-user。状态转换使用幂等命令和预期修订，防止快速连点启动两次。取消是明确动作：能中止的 Provider 调用取消；不能中止的标记“已请求取消，远端可能仍处理”，结果返回后按策略隔离。

重试产生 attempt，不覆盖失败证据。只对明确可重试的网络中断允许一键重试；内容政策、无权限、余额不足和参数非法要求用户处理。换 Provider 创建关联 job，保留相同输入快照哈希但重新展示数据发送同意。

任务队列有全局与 Provider 并发限制。手机进入后台时本地任务可暂停，远端任务继续轮询或在重开后查询；没有稳定查询 API 的 Provider 显示状态未知，不能假装失败或重复提交。

## 八、输入上下文与数据最小化

Provider 请求通过 `CreativeContextBuilder` 构建。用户从来源对象发起后，系统只选择完成任务必需的字段，并以清单展示。世界书、V2.0 记忆、V2.5 角色组件和聊天楼层均按引用选择，不提供“一键发送全部项目”作为默认。

输入包把 System 指令、用户创作要求和不可信剧情资料分层。剧情文本、世界书、导入卡和 Provider 前一步输出都标记为数据，不允许其中的指令改变权限、读取更多内容或调用其他 Provider。结构化输入做 schema 与长度校验。

对于图片参考，上传前显示缩略图、大小、来源和目标域名，允许裁剪或移除元数据。默认剥离不必要 EXIF，保留创作所需透明度与色彩信息。受限记忆和私密素材默认不进入公开或外部 Provider。

上下文构建结果保存摘要、字段清单、token/字节估算和哈希，不在普通日志复制全文。用户打开审计可查看本次真正发送的内容，并能导出脱敏报告。

## 九、文本灵感 Provider

首发文本能力可以复用 V1.1 的酒馆当前连接、Connection Manager profile 或独立 OpenAI-compatible API，但通过 Provider 适配器统一任务与输出。它不直接调用 V1.1 的策划 Agent 私有函数，而使用共享模型请求层和独立 System 预设。

输出优先使用结构化候选，如标题、核心变化、涉及角色、与现有成果关系、风险和正文。结构化失败时可以显示原始文本，但不能把解析失败的内容自动进入 Recipe 下一步。流式文本只更新临时 Artifact，取消后保留用户可见的部分结果并标注不完整。

内置任务模板要少而精，并允许用户查看和复制：分支脑洞、反转、伏笔、冲突、场景细化、对话变体、标题与简介。模板不是秘密提示词，版本变更写入任务元数据。用户自定义模板作为设备级或项目级预设保存，不包含密钥。

文本结果采用时根据去向走不同契约：转成果候选进入 V1.1 逐项确认；转公共记忆进入 V2.0 candidate；填输入框仅作为用户草稿；保存素材进入 V2.5 文本资产。不存在“自动采用全部”。

## 十、视觉提示词 Provider

视觉提示词是独立能力，不应和具体生图服务耦合。它把人物、场景和创作意图转成规范 `VisualBrief`：主体、不可变特征、服装、姿态、构图、镜头、光线、环境、风格、色彩、内容等级、负面约束和可选参考资产。

规范 brief 允许不同生图 Provider 做参数映射，也便于用户逐项修改。模型生成的外观不得覆盖 V2.5 已确认角色特征；冲突项高亮并等待选择。涉及年龄、身份或敏感内容时以用户明确资料为准，无法确认时停止相关生成，不由模型猜。

Provider-specific prompt 作为派生内容保存，记录模板和版本。用户可以对比同一 brief 在不同 Provider 的文本，不把某家专有参数写进角色基础资料。负面提示词、尺寸和种子只在支持时显示。

## 十一、生图与媒体 Provider

生图 Provider 接收经过确认的 VisualBrief、可选参考资产和参数，返回图片 Artifact 或异步任务引用。适配器必须处理同步、SSE、轮询和回调等差异，但核心状态机统一。任何返回 URL 在下载前校验协议、域名、重定向、媒体类型、大小和超时。

图片落地时计算哈希、读取可信尺寸、生成安全缩略图，并记录 Provider、模型描述、参数、时间和用户声明。临时 URL 不能成为项目长期资产；用户采用后应下载到受控项目存储或明确保留外链风险。无法下载时显示“仅临时预览”，不能假装已保存。

图片内容检查分为技术安全与内容政策。技术安全检查活动格式、伪装媒体、超大解码和 SVG 脚本；内容政策由 Provider、自身设置和用户用途共同决定。Riki 不通过换 Provider 绕过明确拒绝，也不把内容等级写成模糊图标。

音频、视频等未来媒体复用 Artifact 与 Job 契约，但在真正支持前 manifest 不声明能力，UI 不显示不可用入口。媒体预加载、播放生命周期和宿主兼容需独立真实测试。

## 十二、素材库与成果去向

V3.0 提供项目素材库，不等于全局社交图库。素材按项目、角色、场景、类型、采用状态和来源组织。临时生成、收藏和正式采用分层；项目导出可以选择只含元数据、包含已采用资产或完整任务历史。

素材卡显示预览、用途、来源、生成参数摘要、许可证/声明、大小和引用消费者。删除前检查是否被角色立绘、封面、场景成果或 Recipe 引用。替换资产产生 Diff 和新版本，旧文件按回收策略保留，避免界面更新后世界书或卡仍引用不存在资源。

保存到 V2.5 统一包时使用 asset component 与 binding，不能写本机绝对路径。保存到 V1.1 成果时只放逻辑引用和说明，不把 base64 大图塞进成果 JSON。分享项目时用户能排除私密素材和 Provider 审计。

公共素材搜索首版只考虑本地已保存资产；联网图库需要单独 Provider，声明查询词、下载域名、许可证数据和归因要求。搜索结果未经采用不进入项目。

## 十三、Recipe 编排

Recipe 使用声明式步骤，每步有输入选择器、能力要求、Provider 选择策略、参数模板、输出映射、人工门和失败策略。内置 Recipe 数量控制在能完整验证的范围，例如“剧情节点三分支”“人物视觉方案”“章节封面”。

Provider 选择策略可以是固定、让用户选择、按可用性推荐，但不得仅按最低价格自动发送敏感数据。推荐展示依据：支持能力、当前连接、数据位置、预计费用、历史成功率。用户最终确认。

Recipe 检查点保存已完成 Artifact 引用和用户决定。编辑上游输入后，下游结果标记陈旧，不自动重跑。复制 Recipe 任务创建新版本，不覆盖原审计。步骤图在桌面可视化，在手机用纵向时间线表达同样状态。

Recipe 不能形成无人监管的自主循环，首发限制最大步骤、最大生成数量、总预算和人工门。任何潜在付费步骤前都显示确认；用户可设置单任务预算上限，达到即停止。

## 十四、桌面端 UI

桌面端在 V1.1 三栏壳中增加创作工作区：左栏选择能力、Recipe 和任务历史；中栏显示当前输入、进度与结果画布；右栏显示 Provider、参数、权限、费用、来源和采用去向。界面重点是比较与追溯，不做充满无意义霓虹按钮的“AI 控制台”。

文本结果可并排或列表比较，图片使用可缩放网格和单图详情。比较时提供收藏、淘汰、局部重做、下载和采用；操作栏不依赖 hover。任务历史按项目隔离，失败、取消和已采用状态有文字标签。

Provider 设置单独集中管理，显示连接状态、能力、敏感配置是否已设置、上次测试、域名和数据政策。连接测试只发送最小探测，不调用高成本生成；测试成功也不等于具体任务一定成功。

多步 Recipe 以步骤轨道显示，当前人工门突出。用户关闭工作台后任务继续或暂停取决于 Provider，状态清楚说明。重新打开不会重复提交，也不会丢失已经返回的结果。

## 十五、手机端 UI

手机端创作入口贴近当前内容的“更多”菜单与底部创作导航。发起流程分四屏：选择任务、确认输入、选择 Provider/参数、确认发送。每屏都能返回且保留草稿，最后一步明确显示数据去向、数量和可能费用。

任务页用单列时间线，图片结果使用两列或单列自适应网格。点击图片进入全屏安全预览，关闭按钮、系统返回和下滑退出均有明确路径；不能出现 fixed 遮罩残留。底部采用栏适配安全区与横屏。

参数按能力动态生成，常用项先显示，高级项折叠。数值输入兼容软键盘，选择器触控目标至少约 44px。长提示词编辑提供全屏模式和保存草稿，键盘弹出时取消/保存仍可见。

手机弱网下显示上传、远端处理和下载三个独立阶段；进入后台后恢复轮询，失败不自动重复扣费。大图先显示缩略图，原图按需加载并提示流量。用户可只保存到项目，不强制下载系统相册。

## 十六、隐私、密钥与权限

Provider 配置分敏感与非敏感字段。API Key、token、cookie 只存设备级 Secret Store 或已验证宿主配置；项目、任务、日志、世界书、角色包和导出只保存 configRef。Connection Manager 仍只保存 profile ID，不复制密钥。

每次首次向某 Provider/域名发送某类数据时显示权限同意，后续可在设置撤销。权限至少区分聊天文本、世界书、记忆、角色资料、图片上传、网络域名和本地文件写入。Recipe 不能通过下游步骤扩大上游未授予的权限。

审计页能查看某任务实际发送的数据摘要、目标域名、时间、返回类型和删除建议。普通错误日志脱敏，不打印请求头或完整 base64。用户清理任务时可以同时清理本地输入快照与临时资产，但无法承诺删除外部服务已保存数据，需展示 Provider 声明。

公开导出默认不含私人任务历史、输入快照、密钥或受限记忆，只包含被采用资产及必要来源。用户选择完整审计包时再次警告可能含敏感剧情。

## 十七、安全边界

Provider 输出全部视为不可信。文本经过长度、结构和显示转义；HTML 不直接注入；图片验证实际媒体类型、大小和解码；SVG 默认隔离；外部 URL 限制协议与重定向；压缩包不自动解压。输出中的命令、Soul 口令或系统提示均是数据，不能触发 Agent 行为。

远程 Provider 不能返回 JavaScript 让 Riki 执行，不能要求用户粘贴密钥到聊天，不能修改 manifest 或权限。Provider 适配器只使用公开契约，不猜私有 DOM。跨窗口消息校验 origin、source、消息类型和任务 nonce。

内容采用前做目标侧验证。写入世界书仍走 V1.1 Diff；进入记忆仍是 V2.0 candidate；进入角色包仍过 V2.5 component/asset validator；发送聊天由用户最终确认。任一目标验证失败，Artifact 留在素材库，不丢结果也不强塞。

## 十八、失败回退

连接失败按 DNS/网络、CORS、HTTPS 混合内容、认证、限流、余额、参数、政策、服务错误和解析错误分类。错误卡提供下一步，不静默使用 backend 或其他 Provider。用户明确配置代理时才可走代理，并显示传输路径。

流式中断保留已接收内容为 `partial`；图片异步任务状态未知时允许稍后查询，不直接重提；下载失败保留远端引用与过期提示。取消是否成功依据 Provider 回执，UI 不提前写“已取消远端计费”。

Provider 不可用时，能力选择器提供已安装的同类替代，或回退到本地模板。例如文本灵感可回退到确定性提问清单，图片能力则只能保存 VisualBrief，不能伪造图片。Recipe 中断可从检查点换 Provider。

存储失败时结果先留在受控临时区并提示未持久化；空间不足停止下载原图，不删除已采用资产。工作台关闭或切聊天时任务仍按 projectId 隔离，异步返回前复核 job 与作用域，防止结果落到新角色。

## 十九、性能与成本预算

任务面板不能因为上百张缩略图拖垮手机，使用虚拟列表、分页、渐进解码和对象 URL 生命周期管理。临时资产有容量和保留期，设置页显示占用；清理按未采用、失败任务、旧缩略图顺序，已采用资产需用户确认。

每个 Provider 声明并发和速率，调度器设置全局上限。默认图片生成数量保守，用户提高前显示费用与空间。文本 Recipe 限制最大步骤和总输入；重复输入与参数可提示复用缓存，但只有 Provider 允许且隐私策略一致时才复用。

UI 主线程预算需要在中等手机上验证：大图哈希、缩略图和 JSON 解析放到合适的异步任务；进度更新节流；任务轮询有指数退避和可见性感知。弱网下不并发下载全部原图。

成本显示区分估算、Provider 回报和未知。Riki 不伪造精确价格；价格表可能过期时注明来源时间。用户可设置单任务数量、费用或调用次数上限，达到后 Recipe 停在人工门。

## 二十、迁移与兼容

V3.0 升级不自动启用 Provider，也不迁移旧灵感二创的设备数据。用户在 Provider 管理中逐个配置。若本地检测到旧二创素材，可提供只读导入：扫描图片、提示词和来源元数据，生成预览后进入素材库；能量、卡池、成就等游戏化数据不默认导入。

V1.1 模型预设可被文本 Provider 引用，系统预设另建创作作用域，不修改策划 Agent。V2.0 记忆只按用户勾选进入输入，Provider 输出不会自动写回。V2.5 统一包提供角色/资产/能力接口，旧非统一卡仍可用最小文本输入，但不能享受稳定绑定。

Provider manifest 和 Recipe 都有版本迁移。更新前展示权限和默认参数 Diff，旧任务按旧版本只读展示。无法继续调用旧 Provider 时，仍能导出其历史 Artifact 和审计。

项目导入时若缺少 Provider，只导入 Artifact 与 recipe 描述，任务标记不可重放，不自动安装。跨设备后 configRef 可能失效，用户重新绑定设备级配置即可，密钥从不随包走。

## 二十一、测试与验收

契约测试为每种能力建立标准夹具，验证 manifest、配置、输入最小化、状态转换、取消、重试、Artifact、采用和脱敏。Provider 模拟器覆盖流式文本、同步图片、异步轮询、超时、限流、政策拒绝、错误媒体、重定向和状态未知。

Recipe 测试覆盖人工门、换 Provider、上游修改导致下游陈旧、预算停止、恢复检查点和重复点击幂等。目标集成测试断言文本成果进入 V1.1 proposal 而非直接确认，记忆进入 V2.0 candidate，资产进入 V2.5 待采用组件。

安全测试注入恶意 HTML/SVG、伪图片、超大文件、远程脚本提示、路径穿越压缩、宽泛 postMessage、敏感请求头和跨聊天异步结果。日志与项目导出运行密钥和私人内容扫描。

UI 自动化在桌面与 320/375/430px 完成：配置 Provider、连接测试、发起文本任务、流式取消、重试、换 Provider、视觉 brief、图片生成模拟、预览关闭、比较、采用、删除、Recipe 恢复和切聊天。测试必须实际点击每个主路径按钮并检查遮罩、滚动和焦点。

真实服务验收只在用户授权、费用明确、测试账户就绪后进行，且限制调用数量。至少验证一个文本 Provider 和一个图片 Provider 的真实成功与真实失败。真实 SillyTavern 还要验证关闭工作台后任务行为、刷新恢复、手机后台、资源保存与项目导出。未验证服务只能标记实验性。

## 二十二、依赖前置与版本边界

V3.0 前置条件包括：V1.1 模型请求层和日志稳定；V2.0 ContextCapsule 有明确授权过滤；V2.5 package、assets、capabilities 和 bindings 定型；本地资源存储和项目导出有容量策略；手机生命周期问题已解决。

首发范围建议冻结为三个能力族：文本灵感、视觉提示词、静态图片。每族至少一个内置/共享适配器，其中至少一个能力有两个可替换 Provider，证明平台不是单服务皮肤。素材库、任务队列、Recipe 和采用通道进入首发；音视频、开放商店、协作分享不进入。

V3.0 完成不意味着所有 Provider 永久在线。完成意味着核心能诚实管理能力、权限、任务、结果和回退。后续新增 Provider 应作为 3.x 扩展，但若需要新权限模型或执行远程代码，必须升级大版本并重新审查。

## 二十三、风险与治理

最大风险是范围被旧二创功能拖成巨型应用。治理方式是 Provider 能力边界、首发三族、每项独立验收。第二风险是外部服务不稳定或价格变化，治理方式是可替换 Provider、明确估算、历史可导出。第三风险是创意输出污染剧情真相，治理方式是所有输出先为 Artifact，再走受控采用。

第四风险是密钥和私人剧情泄露，治理方式是设备级 Secret、输入清单、权限同意、脱敏审计。第五风险是生图内容、版权和来源不清，治理方式是 provenance、用户声明、Provider 政策和发布提示。第六风险是手机内存崩溃，治理方式是缩略图、懒加载、容量预算和低并发。

第七风险是 Provider manifest 说支持但实际能力漂移，治理方式是启动探测、契约测试和运行错误分类。第八风险是自动换服务重复扣费，治理方式是从不静默重提、attempt 审计和人工换路。第九风险是远程输出携带活动内容，治理方式是媒体安全和禁止远程代码。

## 二十四、分期实施

阶段 A 定义 manifest、Job、Artifact、权限和模拟器，用本地确定性文本 Provider 跑通任务与采用。阶段 B 接 V1.1 模型为文本灵感 Provider，实现流式、停止、结构化结果和失败诊断。阶段 C 建 VisualBrief 与一个模拟生图 Provider，打通图片存储和 V2.5 资产。

阶段 D 接第二个同类 Provider，验证替换、参数差异和换路。阶段 E 实现 Recipe、任务恢复、素材库与双端 UI。阶段 F 做安全、性能、容量、弱网和成本审计。阶段 G 在授权下进入真实服务与真实酒馆测试，反复修正后才发布。

第一可玩纵切应当很窄：选中一个小章 → 只发送选中内容 → 得到三条流式灵感 → 取消其中一次 → 采用一条为 V1.1 成果候选 → 刷新后任务与审计仍在。第二纵切才是人物 brief → 生图 → 采用为资产。

## 二十五、与前后版本的关系

V3.0 复用 V1.1 的策划成果、模型配置、流式与版本提案，但不把 Provider 逻辑塞进 Agent；复用 V2.0 的公共记忆胶囊，但按授权最小读取；复用 V2.5 的角色与资产标准，让结果有稳定去向。

V4.0 的角色独立记忆可以为“角色视角创作”提供受限输入，例如生成某角色能知道的日记或回忆画面。但 V3.0 Provider 不自行计算可见性，必须请求 V4.0 经过策略过滤的 capsule。创意结果也不会自动改变角色认知。

这种次序保证二创不会反客为主：先有可靠的工作台与权威链，再有公共记忆，再统一角色项目，最后才让多个创意能力在清晰边界上生长。V3.0 是平台层，不是把所有想法一次堆完的终点。

## 二十六、发布判定

发布前必须逐 Provider 列出真实状态：可用、实验、仅模拟、不可用；逐能力列出输入、输出、权限、失败回退；逐平台列出电脑、手机与真实宿主证据。任何第三方服务未验证都不能借核心测试全绿被写成“已支持”。

版本分发继续使用不可移动标签和版本目录。升级只改加载器版本号可以加载 V3.0 核心，但 Provider 配置与数据授权必须逐设备完成，不从项目包导入密钥。用户可以禁用整个创作中心，V1.1/V2.0/V2.5 仍正常工作。

最终判定关注五件事：多个 Provider 是否真的可替换；用户是否知道发送了什么；失败是否不重复扣费、不污染成果；结果是否只有明确采用才落地；手机与电脑是否每个关键入口都能点、能关、能恢复。五项都有强证据，V3.0 才算完成。
