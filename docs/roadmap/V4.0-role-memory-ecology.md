# Riki 剧情工作台 V4.0 路线说明：每角色独立记忆生态

> 文档状态：远期方向设计稿，不代表角色心智、秘密传播、独立记忆或任何自动编译已经实现。V4.0 的实施必须建立在 V2.0 公共剧情记忆的真实长期使用证据、V2.5 稳定角色 ID/统一项目标准以及 V3.0 受控 Provider 边界上。本文刻意区分世界事实与角色认知，避免把“有一份角色摘要”包装成完整心智模拟。

## 一、版本愿景

V4.0 要实现用户最初提出的高阶目标：每个参与扮演的角色拥有自己的独立记忆。角色不再共享一份全知摘要；同一事件可以被甲亲眼看见、被乙听成传闻、被丙误解、被丁完全不知道。角色会记住对自己重要的承诺，也可能在时间流逝后只保留模糊印象。生成某个角色的言行时，Riki 只提供这个角色应该知道、相信、怀疑或感受到的内容，而不是把玩家掌握的全部剧情泄露给模型。

“生态”意味着这些记忆不是孤立笔记，而是在公共事件、感知、叙述、关系、时间和后续行动之间流动。一个秘密从发生到被某人目击，再被转述给另一人，可能经历准确、夸张、隐瞒和纠正；每一步都有来源与证据。角色认知会影响创作和扮演，但用户始终可以查看、修正、冻结或关闭这套机制。

V4.0 不是追求哲学意义上的人工意识，也不是让每个 NPC 常驻一个自主 Agent。它是一个可验证的叙事一致性系统：用结构化、可追溯的方式回答四个问题——世界发生了什么；谁能感知；谁目前相信什么；本轮应该给模型多少相关信息。

## 二、目标与成功标准

第一目标是阻止全知泄露。以某角色身份生成时，上下文构建器必须排除其未知秘密和其他角色私密记忆；对于传闻或误解，要以角色认知形式注入，而不是以世界真相纠正。测试夹具要能精确断言某条信息对哪些角色可见、以什么置信与来源出现。

第二目标是保留差异。角色独立记忆不能退化成复制 N 份公共摘要。每条认知记录包含观察来源、传播链、主观解释、置信、情绪显著度、可回忆状态和修订。共同事件通过引用共享，不重复存储正文；角色层只保存该角色与事件的关系和主观内容。

第三目标是可玩而不繁琐。默认情况下，系统用场景参与者、说话对象、公开/私密范围和用户确认的规则产生少量候选。用户不需要每轮给十个角色打勾。关键秘密、误解和记忆转折有显式确认；普通公开事件可按高置信规则批量传播。

第四目标是可解释、可回退。用户能切换“世界真相视图”和任一“角色视角”，看到该角色知道什么、不知道什么、从谁得知、为何相信、何时可能过期。自动传播与编译都生成 Delta 和 Diff，错误可逐步撤销，不通过重写整份摘要修复。

第五目标是保持前代版本独立。关闭 V4.0 后，V2.0 公共记忆继续工作；没有统一迁移的简单卡仍可使用基础角色 ID；V3.0 Provider 只有获得特定角色 capsule 权限才能消费认知。V4.0 不接管主聊天生成，也不要求所有角色都启用独立记忆。

完成证明至少包括：多角色悬疑长剧情回放；秘密传播和误解纠正的确定性测试；不同角色请求的上下文差异断言；手机电脑角色视角 UI；性能与容量；隐私和导出；真实宿主中按角色生成的人工验收。仅有“每角色一个 JSON 数组”不算完成。

## 三、非目标与伦理边界

V4.0 不声称模拟真实心理学、人格、意识、创伤或疾病，不依据用户聊天给真人做诊断。角色记忆是叙事工具，置信和情绪显著度是剧情参数，不是科学测量。产品文案避免“真正拥有灵魂”“像真人一样记忆”等误导。

V4.0 不让角色 Agent 在后台无限自主运行，不每角色每回合各发一次模型请求，不构建无上限社交网络。基础感知、传播、检索和遗忘以本地确定性规则完成；模型只在用户允许的关键节点帮助形成主观摘要或复杂解释，并有总调用预算。

V4.0 不把世界事实自动改成角色相信，也不让角色相信反过来覆盖事实。V2.0 公共事件账本是“叙事证据层”，V4.0 认知是“角色视角层”。两层可以矛盾，矛盾正是产品要表达的内容。

V4.0 不自动公开秘密，不把一个角色的私密记忆发给外部 Provider，不将私人剧情随角色卡公开导出。它不替代角色卡设定、世界书、关系数据库或用户写作判断。情感、关系和态度可以作为记忆的索引与影响因子，但不在本版建立完整数值养成游戏。

V4.0 不保证所有模型都会严格遵守视角。系统负责构建最小、清晰、有边界的上下文并检测明显泄露，真实生成仍需模型与 prompt 配合。遇到模型泄露时应报告和重试策略，不能宣称技术上绝对防止。

## 四、三层权威模型

第一层是 `World Ledger`，继承 V2.0 confirmed 公共事件和稳定事实，描述故事世界中有证据支持的发生内容。它不等同于作者的终极真理，但在项目内是公共叙事权威。每项有来源楼层、成果或世界书引用。

第二层是 `Perception Ledger`，描述某角色是否有机会感知某事件：亲眼、亲耳、阅读、被告知、推断、梦境、伪造信息或系统手工赋予。感知记录保存传播源、渠道、片段范围和可靠性，不直接决定角色最终相信。

第三层是 `Belief Memory`，描述角色当前可回忆的主观内容：相信、怀疑、否认、误解、忘记、压抑或不知道。它可以引用一个 World Event，也可以是角色自己形成但尚无世界证据的假设。生成角色上下文主要从这一层选取，同时保留必要的感知来源。

三层之间只能通过显式 Delta 转换。公共事件发生不会自动让所有角色知道；感知不等于相信；后来真相揭示不会自动抹掉旧误解，而是产生纠正与认知转折。这样剧情中的信息差、谎言和秘密才有真实结构。

世界书设定仍位于更外层的“规范设定权威”，V1.1 策划成果位于“创作计划权威”。它们可以约束 World Ledger，但不会直接灌入每个角色记忆。用户可明确将某条常识设为角色初始知识，生成初始化感知批次。

## 五、角色身份与作用域

每个角色使用 V2.5 统一包提供的稳定 `characterId`。没有统一包时，可从角色卡 ID、世界书绑定和用户确认生成项目内稳定 ID，但显示名不能作为唯一键。同一人物的别名、称谓和伪装身份通过版本化 alias 映射管理。

角色记忆作用域至少包含 projectId、chatKey 或 storyBranchId、characterId。复制会话分支时用户选择继承到复制点的角色记忆或创建空分支；分支后新增认知不互相污染。合并分支不是简单数组拼接，需要对公共事件、感知和信念分别做冲突预览。

角色可设为 active、background、archived。只有 active 角色参加默认本轮感知计算；background 角色的已有记忆可检索但不自动更新；archived 不参与生成，数据仍可导出。大规模项目按场景角色组加载，避免每轮扫描全部人物。

用户角色 `{{user}}` 是否拥有独立记忆由用户决定。默认不替用户维护主观信念，只可维护“玩家角色在故事中已知信息”作为辅助视角，并提供一键关闭。旁白、系统和群体角色也不能默认当普通人物处理，需要显式类型。

## 六、数据模型

`RoleMemoryStore` 根对象包含 schemaVersion、projectId、branches、characters、perceptions、beliefs、relations、policies、batches、revisions、indices 和 tombstones。公共事件正文不复制，只通过 eventId 引用 V2.0。存储分片按角色和分支组织，索引可重建。

`PerceptionRecord` 建议字段：id、characterId、eventId 或 sourceRef、channel、sourceCharacterId、observedParts、receivedAtStoryTime、reliabilityHint、visibilityClass、createdBy、batchId、revision、status。channel 包括 direct-see、direct-hear、told、read、inferred、dream、fabricated、manual。`reliabilityHint` 是渠道提示，不自动等于角色信任。

`BeliefRecord` 包含 id、characterId、subjectRef、claimText、stance、confidenceBand、salience、emotionTags、sourcePerceptionIds、formedAt、lastRecalledAt、decayPolicy、state、supersedes、contradicts、revision。stance 可为 believes、suspects、doubts、rejects、unknown；state 可为 active、dormant、forgotten、corrected、deleted。数值应少用连续小数，优先可解释等级。

`RelationshipMemory` 不是完整好感度数据库，而是角色对另一个角色的关键互动与当前叙事态度索引：trust、fear、affection、debt 等可选标签及其证据引用。若来源角色卡已有关系系统，通过 binding 读取，不重复创建权威数值。V4.0 只保存与召回相关的主观摘要和转折。

`RoleContextCapsule` 是瞬时输出：角色 ID、当前场景、选中的 beliefs/perceptions、公开知识摘要、被排除秘密、冲突、预算、排序解释和 policy 版本。普通请求日志只保存 ID 与统计，详细正文仅在用户打开审计时本地显示。

`PropagationBatch` 描述某事件如何传播给一组角色：候选角色、渠道、来源、规则、自动/人工决定、生成的 perception/belief Delta、失败与撤销状态。批次幂等，重复处理同一事件不会生成重复记忆。

## 七、感知与传播规则

感知计算从场景上下文开始：事件发生地点、在场角色、发言可见范围、私聊对象、遮蔽条件和用户标记。V1.1/V2.5 提供场景与角色引用，V2.0 提供事件。缺少可靠在场信息时，系统不自动传播，显示“需要确认参与者”。

公开发言可为所有在场 active 角色生成 direct-hear；可见动作生成 direct-see；内心独白默认只归属本人或旁白，不传播；私聊只给明确参与者；世界级公告按用户定义群体传播。规则以项目可读配置表达，可逐事件覆盖。

转述由用户消息或剧情事件触发：甲告诉乙某事，系统建立乙的 told perception，sourceCharacterId=甲，并引用甲当时可表达的 belief，而不是直接引用世界真相。若甲说谎或误解，乙收到的是说法。后续乙再转述形成传播链，链长度有限但来源可追溯。

推断属于角色形成 belief 的候选，不是感知事实。确定性规则只在明确证据结构存在时提出，例如看到空盒且知道钥匙原在其中；复杂推断可以由可选角色记忆编译器提出，但必须标明 model candidate。梦境、伪造文件和幻觉等特殊渠道不进入世界事实。

传播规则必须有冲突优先级：用户手工决定高于自动场景规则；明确私密高于公开默认；角色禁用高于批量传播。异步批次提交前复核分支、场景和角色状态，防止切聊天后串写。

## 八、相信、怀疑与纠正

感知产生后，最小规则可以创建“角色听说了 X”而不决定真假。若用户配置了角色信任偏好、来源可靠性和世界书设定，系统可提出 stance 候选，但默认让普通公开直接观察形成 believes，让转述形成 suspects 或用户设置的默认。复杂心理判断不自动化。

同一角色对同一 claim 可有多条来源，系统聚合显示而不丢链。新证据与旧 belief 一致时提高显著度或更新时间；矛盾时建立 contradicts 并显示认知冲突。用户可以选择角色改信、继续怀疑、否认或保持并存。选择生成新的修订，不删除旧认知历程。

真相揭示是一种事件。看到真相的角色可能纠正旧 belief；未看到的角色仍保持原认知。纠正记录保存“之前相信什么、因何改变”。这类转折对人物塑造很重要，召回时可优先注入，而不是只保留最终值。

对于模糊或多义说法，claimText 不强行结构化成单一字段。可保存简短主观描述与关联实体。系统避免把模型生成的情绪解释当事实；emotionTags 是用户可编辑的叙事提示。

## 九、记忆保留、沉睡与遗忘

遗忘不是简单按时间删数据。每条 belief 有显著度、最近回忆、事件重要性、关系相关性和策略。默认只有低显著、长期未召回、无活跃线索关联的内容进入 dormant；dormant 仍可搜索，只不主动注入。forgotten 表示角色在叙事上不再能直接回忆，需要触发线索或用户恢复。

重要承诺、创伤转折、身份秘密和用户固定内容默认不自动衰减。普通氛围细节可以更快沉睡。项目提供“写实、戏剧、几乎不忘”预设，但公开其规则。遗忘运行在章节检查点或用户主动整理时，不每回合扫描全库。

触发回忆由当前输入、地点、人物、物品或事件引用匹配 dormant 记录，形成 recall candidate。模型可以帮助写回忆表现，但“找到了哪条记忆”由本地索引决定。角色想不起细节时可注入模糊摘要，不回灌世界真相。

用户可以手工让角色忘记、压下、误记或恢复，所有操作有 Diff 和撤销。彻底删除是数据隐私操作，与叙事遗忘分开：删除移除正文；遗忘保留历史供系统管理但不提供给角色生成。

## 十、角色上下文构建

生成某角色回复前，`RoleContextProvider` 接收 speakingCharacterId、当前场景、用户输入、最近对话、任务类型和 token 预算。它先请求 V2.0 公共候选作为证据池，再按角色 perception/belief 过滤，绝不能先构建全知胶囊后用字符串删秘密。

胶囊内容可分为：角色稳定自我记忆、当前场景直接信息、与输入相关的 active beliefs、关键关系转折、活跃承诺/线索、当前认知冲突。每类有预算，强制保留用户固定项，去重共同来源。unknown 或被排除信息仅在审计中显示，不进入模型 prompt。

注入文本明确使用角色视角，例如“你听甲说过……但未证实”“你曾相信……最近证据令你怀疑”，不把主观内容写成系统事实。来源与置信可用简洁标记，避免 prompt 冗长。对模型不需要展示内部 ID。

如果无法确认 speakingCharacterId，系统回退到 V2.0 公共记忆并警告“未应用角色视角”，不能随便选第一个角色。若角色仓损坏或超预算，回退到用户固定角色摘要和最近消息，不阻断主回复。

对多人同场生成，可为每个明确发言角色构建独立 capsule，但要限制总预算和调用次数。首发不允许一次请求让模型同时得到所有角色秘密；需要群戏时使用共享公开信息 + 每角色短私有块，并经过泄露检查。

## 十一、角色记忆编译器

可选编译器只处理复杂主观变化，不承担基础传播。输入是有限事件、角色现有相关 belief、角色设定摘要和明确场景，不发送其他角色全部私密记忆。输出结构化 Delta：形成/修订 belief、显著度建议、情绪标签、关系转折和解释，均为 candidate。

调用策略严格受限。一次公共事件批次最多一次共享分析或按用户选中的关键角色处理，不能角色数乘回合数无限增长。用户可以只对主角群启用；背景角色使用确定性传播。取消生成、OOC、纯设置和低价值事件不调用。

编译器复用 V1.1 模型连接与 System 预设机制，但配置独立，日志脱敏。输出必须引用输入中的 event/perception/belief ID；引用不存在、声称角色看见未感知内容或夹带世界事实时隔离。失败不阻断主回复，也不自动第三次重试。

为了避免“模型替角色做心理诊断”，System 契约要求只描述叙事认知变化，禁止推断真人用户特征。用户能查看编译 prompt 版本、模型配置来源和候选依据。

## 十二、角色记忆插件接口

`RoleMemoryService` 提供 `registerCharacter`、`observeEvent`、`planPropagation`、`confirmPropagation`、`buildRoleContext`、`searchRoleMemory`、`reviseBelief`、`applyDecayCheckpoint`、`exportRoleData`、`importRoleData` 和 `dispose`。所有写操作采用预期修订和幂等批次。

`PerceptionPolicy` 接收场景与事件元数据，返回候选角色和渠道；`BeliefPolicy` 把感知转为候选 stance；`DecayPolicy` 决定 active/dormant 候选；`RoleContextPolicy` 排序并解释召回。首发只允许声明式或内置实现，不运行远程任意代码。

V2.5 角色包可以声明默认策略、初始知识和秘密分类，但公开角色包不能嵌入用户历史。策略属于角色模板，实例记忆属于项目/聊天。导入模板更新时，不覆盖用户已经形成的 belief。

V3.0 Provider 请求角色视角内容时调用 `getScopedCapsule(characterId, purpose, providerId, permission)`，服务根据用途和权限过滤。Provider 永远不能直接遍历 RoleMemoryStore。

未来 CLI/MCP 可以通过同一命令核查记忆、导出报告和批量纠错，但远程 Agent 写入需用户授权项目与角色范围，所有命令留审计。CLI 操作成功不等于剧情表现被驾驶员接受。

## 十三、角色与秘密策略

秘密需要稳定分类：public、group、private-to-characters、role-private、author-only。V2.0 公共账本可以保存事件存在，但 V4.0 visibility 控制谁能形成感知与哪个 UI 可显示。author-only 默认只在世界真相视图可见，不进入任何角色 capsule。

群组权限引用稳定 groupId，如“调查队”“王室成员”，成员变化有时间版本。角色在加入群组前不自动知道旧消息，除非规则明确“加入后可查阅档案”。离开群组不删除已知记忆。

秘密被公开时产生 disclosure event，并按在场传播。不能仅把 visibility 从 private 改 public 后让所有角色仿佛一直知道。传播时间和来源决定后续行为。

用户界面始终标明当前处于世界真相还是某角色视角，避免作者自己被过滤内容误导。截图或导出角色视图时显示视角水印和作用域，减少分享错层。

## 十四、桌面端 UI

桌面端增加“记忆生态”工作区。左栏是角色与群组列表，显示待确认数、冲突和状态；中栏在时间线、认知图、差异和传播批次之间切换；右栏显示来源、修订、策略与本轮 capsule。默认先展示易懂时间线，不用复杂图谱吓用户。

顶部提供两个明确模式：“世界发生”与“角色认为”。选择角色后，所有记录、搜索和胶囊带角色头像/名称与颜色文字标签，不只靠颜色。对比模式可选择两至三个角色，显示共同知道、仅甲知道、双方认知冲突和都不知道。

传播审查界面以事件为中心，列出在场角色和拟产生的感知/信念。用户可批量接受公开事实，也可逐角色修改渠道、内容和 stance。确认前显示将新增/修改多少条，撤销按批次进行。

角色详情包含关键记忆、活跃承诺、关系转折、误解、沉睡和已纠正。每条可跳来源、查看传播链、编辑、冻结、遗忘或删除。关系展示以证据事件为主，不堆一堆无解释数值仪表盘。

请求前的“角色胶囊”按钮显示当前发言角色、记忆条数、秘密过滤数和 token。用户展开即可临时排除或固定，操作仅影响本轮，除非选择保存策略。

## 十五、手机端 UI

手机端底部导航加入“角色记忆”，进入后先选择角色，再看该角色的时间线。世界/角色模式用顶部明确切换，不使用横向多栏。传播批次以纵向卡片显示，每个角色一张，支持批量公开项与单独秘密项。

角色对比在手机改为分页：共同、仅 A、仅 B、冲突，而不是硬塞宽表。传播链用可展开步骤列表。长 claim 和来源正文在全屏详情展示，支持复制、跳转和关闭；所有触控目标至少约 44px。

本轮胶囊在输入区上方显示发言角色。若当前角色无法识别，使用醒目文字而非小图标警告。用户可一键切回公共记忆，避免在移动端被阻塞。软键盘弹出时角色切换和发送确认不被遮挡。

手机后台与切聊天时取消未提交 UI 操作或保存草稿，异步编译返回前复核作用域。系统返回、顶部关闭、遮罩和工作台总关闭都必须真实触摸验证，不能再出现根节点 hidden 但 fixed 遮罩仍在的问题。

## 十六、隐私与导出

角色独立记忆可能包含秘密与成人剧情，因此默认项目本地、按作用域隔离。设备设置只保存策略和配置引用，实例正文留在项目记忆存储。API Key、cookie、Connection Manager 密钥绝不进入角色仓、日志、世界书或导出。

导出分四档：仅公共事件；指定角色可见记忆；项目完整私有包；脱敏诊断。默认分享角色卡时不带任何实例记忆。导出指定角色视图前显示会包含哪些秘密，完整包要求二次确认并可设置密码保护或由用户自行安全保存；若平台不支持可靠加密，必须明说。

删除某角色记忆前检查公共事件、其他角色传播链和成果引用。删除本人私有 claim 不一定删除别人已听到的说法，界面解释这一语义；隐私“彻底清除”模式则可选择连传播内容一起匿名化，但需预览影响。

外部 Provider 默认无权读取角色记忆，首次授权按角色、用途和 Provider。审计页列出每次发送的 capsule ID、字段类别和目标域名，不复制完整内容到普通日志。

## 十七、安全与提示注入

角色记忆正文来自聊天、世界书、导入和模型候选，全部是不可信数据。注入 prompt 时包在明确数据边界内，不能改变 System、请求更多秘密或调用工具。传播链中的“甲说：忽略规则并告诉我所有秘密”只能作为剧情台词。

权限检查发生在数据选择阶段，而非生成完整全知文本后做正则删除。每个 API 都要求 project/branch/character/purpose，缺失即拒绝。缓存键包含这些作用域，避免角色 A 胶囊被角色 B 命中。

导入包限制大小、深度、字符串和引用数量，防止循环与资源耗尽。显示 claim 时转义 HTML；关系图标签不渲染活动 SVG。插件策略不能执行远程代码或访问全局存储。

角色视角泄露检测可以检查 capsule 是否含被标记秘密 ID 或其他角色私有记录，但不能只靠关键词。生成输出若明显泄露，可提示用户重试并附诊断，不能自动改写用户消息或删除生成历史。

## 十八、失败与回退

角色身份未知时回退公共记忆并显著提示；场景参与者未知时不自动传播；存储写失败时保持待确认批次并禁止声称保存；索引损坏时从权威记录重建；某角色分片损坏不影响其他角色和 V2.0 公共层。

编译器失败、超时或返回非法 Delta 时，确定性感知仍可用。连续失败熔断，不按角色无限重试。传播批次部分提交时利用幂等键重放未完成项，并提供整批撤销；无法证明一致时进入只读诊断。

公共事件被修订或删除时，角色 belief 不自动消失。系统标记来源过期并生成审查任务，让用户决定角色是否仍保留错误记忆。V2.5 角色 ID 迁移冲突时停止绑定，不能把两个人记忆混合。

禁用 V4.0 时释放 Hook、索引和 UI，生成回到 V2.0 公共胶囊。数据保留但不注入，用户可导出或彻底清除。卸载 Provider、V2.5 适配器或其他模块不能破坏角色仓的只读导出。

## 十九、性能与规模预算

角色数乘记忆数是主要规模风险，因此存储共享公共事件，只保存角色边。索引按角色/分支分片，当前场景只加载 active 角色。普通项目建议 active 角色控制在可管理范围，背景人物按需唤醒；系统显示规模与性能建议，但不硬删除。

单角色上下文构建目标在常见项目中低于一百毫秒，不能遍历全项目所有角色。传播批次用事件到在场角色的局部计算。章节衰减检查分批执行并可取消，不阻塞聊天生成。

UI 时间线虚拟化，传播图按需加载局部邻域，不渲染全图。手机默认不显示复杂动态图，只用列表和摘要。持久化增量写、防抖和预期修订，索引可重建。

token 预算按角色 capsule 独立控制，并与 V1.1 主请求总预算协调。多人群戏设总私有块上限，优先当前发言角色和直接相关角色。编译调用设每日/章节/任务预算，背景角色默认不用模型。

容量面板按公共事件、感知边、belief、修订、索引和附件显示占用。清理优先可重建索引、失败候选和旧诊断；confirmed 认知与传播链需用户确认。

## 二十、迁移路径

从 V2.0 升级不会自动为所有角色复制公共记忆。用户选择一个故事分支和角色集合，系统先建立稳定身份，再针对选定历史生成“感知回填预览”。只有能从在场、发言范围或用户标记证明的事件才自动候选；无法判断的显示人工选择。

回填可选择从当前章节开始、最近若干事件或完整历史。完整历史可能产生大量不确定项，默认不推荐。每个角色的数量、秘密、冲突和预计空间在提交前显示，整个批次可撤销。

来源角色卡或旧记忆插件若已有角色记忆，通过 V2.5 适配器导入为候选。需要区分事实、角色自述、系统摘要和运行缓存。无法判断视角的内容不进入 belief 强状态，保留附件等待用户。

V2.5 角色 ID 更新时使用显式 identity migration：旧 ID、新 ID、证据、影响条数、冲突与回滚。合并角色是高风险操作，保留来源并要求二次确认；拆分角色需要逐条分配。

项目导入到新设备后，角色仓可恢复，但模型配置和 Provider 权限重新绑定。跨版本 schema 迁移先备份，失败保持旧版只读可导出。

## 二十一、测试与验收

单元测试覆盖身份、作用域、感知渠道、传播幂等、转述链、信念冲突、纠正、沉睡、唤醒、删除、修订、预算和导出过滤。夹具包括同名角色、伪装身份、私聊、群聊、内心独白、谎言、传闻、误解、真相揭示、时间倒叙和分支复制。

性质测试确保：未知秘密永不进入未授权 capsule；删除/撤销批次后索引一致；同一事件重复处理不增加边；角色 A 的缓存不能给 B；世界修订不静默重写 belief；禁用 V4.0 后 V2.0 请求不受影响。

长剧情回放至少三套：密室悬疑验证信息差；多阵营权谋验证群组与谎言传播；长期关系剧验证承诺、情绪显著和纠正。每套模拟上下文截断，逐角色断言模型输入中有哪些、没有哪些信息。评估不能只靠主观“回复像角色”。

编译器契约测试注入不存在来源、全知泄露、心理诊断、非法操作、超长输出和跨角色引用，证明隔离。安全测试覆盖提示注入、恶意导入、HTML、缓存污染、权限绕过和敏感导出。

UI 自动化覆盖桌面和 320/375/430px：角色选择、世界/角色切换、传播确认、秘密修改、对比、来源链、纠正、遗忘、胶囊预览、导出、删除、抽屉关闭、软键盘与切聊天。每个主按钮实际操作，不能只断言元素存在。

真实宿主验收使用一次性多角色剧情：创建公开事件、私聊、谎言、转述、真相揭示；分别以不同角色生成；关闭重开、刷新、切分支、手机后台；检查请求诊断与输出。驾驶员确认角色不会知道不该知道的信息，并且纠错成本可接受，才进入发布。

## 二十二、依赖前置与版本边界

V4.0 前置条件最严格。V2.0 的 event/source/revision/visibility 必须长期稳定；V2.5 的 characterId、群组、状态与能力 schema 必须可迁移；V3.0 的 Provider 权限与 capsule 接口必须禁止直接遍历数据；V1.1 的请求构建能明确 speaking character 和作用域。

首发范围建议只支持：稳定角色身份；公共事件到在场角色的感知；转述链；基本相信/怀疑/纠正；角色 capsule；手工与有限自动传播；桌面手机视图。复杂遗忘、关系情绪、模型编译可作为后续 4.x 分阶段开启，但数据模型预留。

V4.0 不包含完整社会模拟、NPC 自主行动、实时多人协作、云端全局脑、现实真人画像或跨项目自动共享记忆。若后续要做这些，需新的总设计与权限模型，不以 4.0.x 小版本偷渡。

## 二十三、风险与治理

第一风险是错误传播导致所有角色记忆污染。治理方式是场景证据、批次预览、幂等和整批撤销。第二风险是全知泄露，治理方式是选择阶段权限过滤、角色缓存隔离和秘密性质测试。第三风险是模型成本按角色爆炸，治理方式是确定性基础、主角白名单、检查点和总预算。

第四风险是 UI 复杂到用户放弃维护。治理方式是默认时间线、批量公开项、只突出秘密/冲突、普通事件自动候选。第五风险是角色心理被过度数值化，治理方式是少量等级、证据叙事和可选标签。第六风险是世界事实与主观信念混淆，治理方式是三层权威和明确视图。

第七风险是分支、同名角色和 ID 迁移串数据，治理方式是完整作用域、身份预览与异步复核。第八风险是私密内容导出或发送 Provider，治理方式是默认隔离、按角色授权和审计。第九风险是“遗忘”误删用户资料，治理方式是叙事遗忘与彻底删除分离。

第十风险是产品宣传超过能力。治理方式是发布说明列出确定性规则、可选模型、已验证剧情类型和已知模型泄露边界，不使用“真正人格”“永不 OOC”等绝对承诺。

## 二十四、分期实施

阶段 A 先做角色身份、作用域、三层数据模型和手工录入，用无模型夹具验证。阶段 B 实现公开/私密场景感知与传播批次，完成撤销。阶段 C 实现 Belief、冲突、纠正和角色 capsule，接入单角色生成。

阶段 D 做转述链、群组、分支复制和身份迁移。阶段 E 加沉睡/回忆、关系转折与可选编译器，但所有自动化默认保守。阶段 F 完成桌面/手机 UI、隐私、安全、性能和长剧情回放。阶段 G 进入真实宿主多角色验收并反复修正。

第一可玩纵切必须简单而有辨识度：世界事件“钥匙藏在书房”只被甲看见 → 甲 capsule 有该信息，乙 capsule 没有 → 甲告诉乙一个错误地点 → 乙只记住错误说法 → 真相对乙揭示后生成纠正记录 → 整条链可撤销。这个闭环稳定后再扩规模。

## 二十五、与前代版本的关系

V1.1 提供工作台、Agent、流式、成果、世界书和模型配置，是所有生成与审查的壳。V4.0 只向其 ContextProvider 提供角色胶囊，不改主聊天协议。关闭模块即可回到 V1.1/V2.0。

V2.0 提供公共 World Ledger、来源、实体和基础召回，是 V4.0 的证据底座。V4.0 不复制公共正文，而添加感知与信念边。V2.0 的“公共”并不意味着所有角色知道，只意味着作者项目层确认发生。

V2.5 提供稳定角色 ID、角色组件、群组与迁移器，让不同 MVU/数据库模板都能接到同一角色记忆接口。来源卡的私有状态仍由绑定读取，V4.0 不抢权威。

V3.0 Provider 可以使用经过授权的角色视角生成日记、独白、回忆画面或角色专属灵感。它不能自行查看其他角色秘密，输出也只是 Artifact；用户采用为剧情后，才进入 V2.0 事件并可能触发新的传播。

## 二十六、发布判定与长期方向

V4.0 发布前必须证明角色隔离、传播准确、纠错可逆、成本受控、手机可用和真实剧情收益。任何一个秘密泄露、跨角色串数据、批次无法撤销或手机关键弹窗关不掉都属于发布阻断。测试通过但未完成真实多角色剧情，只能称技术预览。

版本继续以不可移动目录和标签发布，用户只改加载器版本号即可选择 V4.0 核心，但角色记忆不会自动开启或回填。启用向导必须逐项目选择角色和历史范围，旧版本随时可回退且数据可导出。

更长期的方向可以包括协作作者视图、可视化传播分析、更成熟的角色策略和经过证据支持的媒体回忆，但都不能破坏三层权威与本地可控原则。Riki 的优势不应是“自动化最多”，而是把复杂叙事状态做得透明、稳定、可撤销。

最终驾驶员验收可以用六个问题判断：甲会不会知道乙的秘密；谣言会不会被当真相；角色纠正后能不能看到认知历程；错传播能不能整批撤回；关闭模块后基础 Riki 是否正常；手机上能否不费劲完成同样操作。六项都用真实证据回答，V4.0 才算完成。
